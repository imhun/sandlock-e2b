# 环境变量参考

本文件是 worker / 控制面 / agent / quota-agent 的**运行期开关速查**，从旧 `README.md`
的「环境变量」一节原样搬来（2026-10-01）。**权威口径**是各组件的 `config.py` 与
[spec.md](../spec.md) §7.2；每个变量的完整语义、默认值来源、以及"改错了会怎样"，
以对应组件的 `config.py` 注释为最终答案。

> ⚠ 这份表里保留了**已退役**的条目（`E2B_PRIV_HELPERS`、`E2B_PRIV_HELPER_SOCKET`），
> 目的是让旧部署的配置有个解释；代码不再读它们，设了也只是惰性残留。

控制面与 envd 的全部配置见 spec §7.2，默认值与之一致。常用：

| 变量 | 默认 | 说明 |
|------|------|------|
| `E2B_API_KEY` / `E2B_API_KEYS` | `local-key` | 控制面 API Key |
| `E2B_WORKSPACE_BASE` | `tmp/sandboxes` | 沙箱工作目录 |
| `E2B_STATE_BASE` / `E2B_NODE_STATE_BASE` | 前者空（= 工作区根）、后者空 | 平台自己的文件放在哪两根上。`E2B_STATE_BASE`（N27）是**共享**那根：`_runtime/<id>/sandbox.json` 记录、命令日志、`.checkpoints/**`，以及 uid 池回落路径（`UidPool.acquire`）自己的 `.uid_pool.lock` 与 `.uid_reservations/`（**N57 修**：`acquire` 的"读记录 → 挑 uid → 写标记"临界区必须跨节点互斥，锁与预约标记因此回到共享 base；`claim` 常态路径不碰它们） —— 记录是**舰队级 uid 账本的索引**（`envd_service/uid_pool.py::_recorded_uids` 枚举它），checkpoint 会被**别的节点**在 resume 时读，所以它必须共享。`E2B_NODE_STATE_BASE`（N57 / Task 4）是**节点本地**那根：建箱 `prepare` 写的 `.creating` 标记与 `disk-stats` 种子、`.route-b/**` 的 slot 文档。判据只有一条：**这份数据有没有另一个节点上的读者**。k8s 出厂值 = `/var/lib/e2b-sandboxes/state` + `/var/lib/e2b/state`（hostPath，节点盘，与 `E2B_IMAGE_CACHE_DIR` 同一块盘；`c3-agent` 的 `workspace-root-init` 建它并交给 65534）。**两个都不设**时是 Task 4 之前的形状逐字节不变（compose、测试、`local://` 都不设）。为什么值得分：共享卷是 NFS，一次元数据往返 ~13 ms（Task 1 §1.1），`prepare` 原先要为它写的每个小件各付一次（**已部署形状**=标记 + `disk-stats` 种子两笔；`uid_pool.acquire` 那条**回落**路径——payload 不带 `hostUID`——还会多付 `.uid_pool.lock` 与 `.uid_reservations/` 两笔，本机探针量到的 `before=14` 就是这条形状）；本地量法见 `deploy/scripts/acceptance/node_state_split_local_probe.py`（`before=14 / after=4`，那 4 笔正是池自己的文件），集群量法见 `prepare_phase_cost_probe.py`。 |
| `E2B_SHARED_VOLUME_ROOT` | 空（未命名） | **共享导出根**：`_snapshots`（快照记录 + `fs.tar` 载荷）、`_migrate`（迁移暂存）、`_volumes`/`_volumes/_meta`、`_images`、`_secrets`、`_templates`、`_builds` 都在它下面（`gateway_common/paths.py::platform_namespace_root`）。**k8s 出厂值 `/var/lib/e2b-sandboxes`**；compose 的 `docker-compose.prod.yml` 也设它。读者有三个：控制面（`control_plane/config.py::shared_volume_root`，`SnapshotRegistry` 的 `platform_root` 与 `_migrate` subPath 的推导）、worker（`envd_service/config.py`，快照 payload 与迁移导出/导入）、每节点 agent 的面 B（`c3_agent/config.py` + `c3_agent/fileops.py` 写进子进程 env，`priv_common.c::priv_shared_volume_root` 是**白名单的一根**）。**改错了会怎样**：不设（或设成树根）时 `snapshot_payload_dir` 的 `shared_root` 落回 `E2B_WORKSPACE_BASE` ⇒ 快照载荷写进**节点本地**的树根，别的节点的控制面/agent 读不到（建箱时表现为 `Snapshot … not found on this node`）；设成比真卷更宽/更窄的路径会让 `e2b-maint` 的白名单与 `build_volume_mounts` 的"卷必须在共享根之下"检查同时失准（前者是"能改到不该改的路径"，后者是建箱 400）。**N73**：在**控制面**上这个变量只作**判据/导出根** —— 卷仓根 = `<shared_volume_root>/_volumes`，卷仓根另有权威名 `E2B_VOLUME_STORE_ROOT`（下一行）。Task 20 之前控制面把它当**卷仓根本身**，于是设了它就把卷建到只读的导出根上（`0.1.0-943` 实测 `POST /volumes` 500/`EROFS`）。 |
| `E2B_VOLUME_STORE_ROOT` | 空（未命名 ⇒ 按下面的顺序派生） | **控制面卷仓根的唯一权威**（N73 新立；只有控制面读它 —— `control_plane/config.py::volume_store_root`，派生在 `control_plane/app.py::_derive_volume_store_root`）。**派生顺序**：① 设了它 ⇒ 用它；② 否则 `E2B_SHARED_VOLUME_ROOT` 设了 ⇒ 用它 + `/_volumes`；③ 两者都没设 ⇒ `<platform_root>/"_volumes"`（k8s 今天的形状，逐字不变；k8s 清单因此**不设**这一行）。**何时设**：控制面与 worker 共享同一个导出根、但卷仓另有位置时；或要把 compose 形态既有的旧式平铺卷（`<shared_volume_root>/vol_*`）留在原地时（把它设成 `<shared_volume_root>`）。**自保护**：派生时若发现 `<shared_volume_root>/vol_*` 这类目录存在，而派生出的卷仓根**不是**那个目录本身，控制面**按名拒绝启动**（`LegacyVolumeLayoutError` / `legacy-flat-volume-layout`）：点出旧卷路径与目标卷仓根，要求先迁移/N73，**绝不**静默改路径把老卷藏起来；没有旧式卷 ⇒ 正常用新规则。**改错了会怎样**：卷仓根落在 worker 的 `E2B_SHARED_VOLUME_ROOT` 之外会让 `build_volume_mounts` 的"卷必须在共享根之下"检查失准（建箱 400），别的节点也读不到那份卷。 |
| `E2B_TREES_SHARED` | 空（未命名 ⇒ 沿用 `bool(E2B_SHARED_VOLUME_ROOT)`） | **沙箱树在不在共享存储上的判据**（Task 0 新立；只有**控制面**读它 —— `control_plane/config.py::_trees_shared_from_env`）。取值是闭集合：只有 `1`/`true`/`yes`/`on` 算"共享"；**任何其它非空值（含 `0`）都算"本地"**（刻意如此：变量的**存在**就是声明，打错字不会静默把树翻回共享）；**空值 = 未命名**，沿用旧问题 `bool(E2B_SHARED_VOLUME_ROOT)`，于是本开关之前的部署行为逐字节不变。k8s 出厂值 = **`0`**（树在本节点 hostPath `/var/lib/e2b/workspaces`，见 `E2B_WORKSPACE_BASE`）。**改错了会怎样**：这一个值同时决定迁移的三件事 —— 导不导 tar、在目标写不写树、留不留源节点的树 —— 判据与树根不一致就是**静默建空树 + 源节点的树留下且只被判 `protected`**（不导出 → 记录改指 → 目标端空树）。⚠ **它也是本批的回退杆，但回退不是翻这一个字符**：还要把 `E2B_WORKSPACE_BASE` 在四条 env 上一起改回 `<export>/workspaces`，并做一次"把活树从节点本地搬回共享卷、记录一起改指"的数据步骤 —— 逐条见 `docs/deploy-clusters.md` §7.33.5。 |
| `E2B_TREE_COPY_MAX_BYTES` | `1342177280`（1.25 GiB）；`0` = 不限 | **一次树拷贝的字节上限**（Task 3）：迁移的导出/导入、快照载荷的写与拆、以及 agent 面 B 的材料化。三个组件共读同一默认（`gateway_common/archive.py::DEFAULT_TREE_COPY_MAX_BYTES`；`control_plane/config.py`、`envd_service/config.py`、`c3_agent/config.py`），k8s 三份清单显式给 `1342177280`。越过它是**具名拒绝** `tree-copy-too-large`（控制面/worker 413；`materialize` 走 `tree-too-large`），**绝不截断**。默认 = 单沙箱默认配额（1 GiB）+ 归档自身开销：**不能小于单沙箱配额**，否则"一个装满的沙箱"这种最不该被拒的合法迁移会被拒。**改大了会怎样**：整棵树经过控制面/`maint` 进程的内存与页缓存没有上限（900 MiB 的恢复已经把 512 MiB 的 `maint` OOM 过一次，`docs/create-local-first-design.md` §3.0），所以 `maint` 的 limit 抬到 2 GiB；**改小了的代价是合法恢复 413**。 |
| `E2B_TREE_COPY_WINDOW_BYTES` | `67108864`（64 MiB）；`0` = 关闭窗口 | **拷贝每走这么多字节就丢一次页缓存**（`POSIX_FADV_DONTNEED`，Task 3），与上一行同一批读者（三份 `config.py`），k8s 三份清单显式给 `67108864`。它把峰值从"整份拷贝 ×2.9"压到"一个窗口 + 在途脏页"。**改错了会怎样**：设 `0` ⇒ 页缓存在 `maint`/控制面里随拷贝线性增长（内存压力、可能 OOM），**正确性不受影响**；设得过小只是多几次 `fadvise` 系统调用。两者都是尽力而为，`drop_page_cache` 失败不报错（不是正确性问题）。 |
| `E2B_ARCHIVE_MAX_MEMBERS` | `1500000`（1.5 M）；`0` = 关闭上限 | **解包侧的一次成员数上限**（N63，Task 4）：快照恢复、迁移导入、agent 面 B 材料化三条解包路径共读（`gateway_common/archive.py::DEFAULT_ARCHIVE_MAX_MEMBERS` / `resolve_member_max()`）。解包时**成员数据是流式的，成员索引不是** —— CPython 的 `TarFile.next()` 无条件 `members.append`，实测索引 ~429 B/成员 ⇒ 2 M 个极小成员光索引就 ~0.9 GB，而 `E2B_TREE_COPY_MAX_BYTES`（1.25 GiB）**bound 字节但不消除索引**（2 M 个空成员 ≈ 1 GiB 的 512 B 头，正好在字节上限内）。越过它是**具名拒绝** `ArchiveRefusal(reason="archive-too-many-members")`，**绝不截断**。默认值按 `maint` 的 2 GiB limit 反推：1.5 M 成员实测解包**索引峰值** `822,267,904 B = 0.77 GiB`（约 38%；**这是 RSS-only 读数**，cgroup `memory.max` 还要算那 1.5 M 个新文件的 inode/dentry slab 与文件页缓存）。**改大了会怎样**：`maint` 有 OOM 风险（索引 ~429 B/成员线性增长）；**改小了的代价是合法的大成员数树被具名拒绝**（可调，或设 `0` 关闭上限）。**上限只在读侧** ⇒ 可以先建出一个超过上限的快照，恢复时才按名拒绝（写入侧不看这个上限）。 |
| `E2B_ARCHIVE_MAX_SECONDS` | `180`（秒，浮点可）；`0` = 关闭预算 | **解包侧的一次墙钟时间预算**（N67，与 N63 的成员数上限同批）：快照恢复、迁移导入、agent 面 B 材料化三条解包路径共读（`gateway_common/archive.py::DEFAULT_ARCHIVE_MAX_SECONDS` / `resolve_time_budget()`）。成员数上限只 bound **内存**、不 bound **时间**（1.5 M 成员实测解包约 **12 min CPU**），所以再加这条：解包每走过 `TIME_BUDGET_CHECK_EVERY = 4096` 个成员（外加第 1 个成员）看一次 `monotonic()`，超过预算即**具名拒绝** `ArchiveRefusal(reason="archive-time-budget-exceeded")`（detail 带上限、已耗时、已见成员数与 env 名），**绝不截断**；agent 面把这条与成员数上限一并折成 **502**（`c3_agent/app.py::_refusal_status`，N69）。**改大了会怎样**：合法的大成员树能跑多久就跑多久，占着 `maint` 的 2 GiB 与一个解包槽；**改小了的代价是合法的大树被具名拒绝**（可调，或设 `0` 关闭）。**上限只在读侧** ⇒ 可以先建出一个超预算的快照，恢复时才按名拒绝。取值背景见 `docs/open-issues.md` N67 行。 |
| `E2B_BASE_IMAGE` | 未配置 | `base` 模板基础镜像；配置后启用镜像 rootfs |
| `E2B_TEMPLATE_IMAGES` | `{}` | 模板 ID → 基础镜像 JSON 映射 |
| `E2B_EXECUTOR` | `auto` | `auto`/`local`/`sandlock`；`auto` 只对**顶层包不存在**（`ModuleNotFoundError: No module named 'sandlock'`）回落 `local`，包在但坏（版本不匹配/缺符号/半升级树少 `sandlock.*` 子模块）一律 fail closed（B1 fix round 2/3） |
| `E2B_COMMAND_STREAM_LIMIT_MB` | `32`；`0` = 不限 | **每个命令输出流在 worker 里的字节预算**（SEC-K0S-003，2026-10-03 修）。四个交接点共用它：① 读线程→事件循环的闸门（`stream_budget.ThreadHandoff`，预算用尽时**读线程等待** ⇒ 命令的管道满 ⇒ 命令自己的写阻塞 —— 真背压、**零丢失**）；② 进程输出队列与 ③ 订阅者队列（`ByteBudgetQueue`，字节 + 条数双界，满了丢块 + 一次 `... output truncated ...` 内联标记 + WARNING）；④ 中继**发出去**的字节（`rpc.py::_consume_stream`，切点打标记后继续抽干队列，`end` 照常送达）。另有 `E2B_COMMAND_CAPTURE_LIMIT_MB`（默认 10）只管**回放**缓冲，与它无关。**改小**：慢客户端更早看到截断、命令更早被背压拖慢；**改大**：单流占更多 worker 内存（worker 限额 4 GiB）。⚠ **`0` 关闭全部四处封顶，会回到 2026-09-30 那次"一条 `yes` 打爆 worker（OOMKilled exit 137）"的形状** —— 除排障外不要设。 |
| `E2B_PRIV_HELPERS` | **已移除（N52，2026-09-30）** | Track F 的本地 broker 开关：`auto` 让 uid 65534 的 worker 用镜像里 `/var/lib/e2b-priv/` 的两个 file-capability 二进制（`e2b-slot-spawn`、`e2b-maint`）完成"以池内 uid 起 route-B 槽位"和"把工作区/slice 交给沙箱 uid"两步，`off` 则保持进程内 E5.1 形态。**这个形态整体退役了**：二进制、`exec` transport、C1 的 `socket` broker 与这个开关都不再存在，worker 的特权文件步骤全部由每节点 agent 以 `{sandbox_id, op}` 代做（见 `E2B_PRIV_HELPER_TRANSPORT`）。旧的仓库里若还设着这个变量，它现在是**惰性**的（代码不再读它）；真需要那个形态时从 git 取回当时的清单 + 镜像。`e2b-maint` 只存在于 **agent 镜像**（`deploy/docker/Dockerfile.agent` 的 `/var/lib/e2b-priv/`），它的路径白名单是五根：`E2B_WORKSPACE_BASE`、`E2B_NODE_STATE_BASE`（N57 / Task 4）、`E2B_STATE_BASE`（N27）、`E2B_SHARED_VOLUME_ROOT`、以及仅当显式非空时的 `E2B_IMAGE_CACHE_DIR`（沙箱 secret 落在 `<image_cache_dir>/secrets/<id>/`）。容器 **BND**：worker 是**空集**，**绝不要加 no-new-privileges**（NNP=1 会让 agent 面 A 的 `as_uid` 的 file caps 静默失效）。 |
| `E2B_PRIV_HELPER_TRANSPORT` | `auto`（出厂 manifest 显式 `agent`） | 文件操作走哪条路。`agent`（**C3 Task 4 片 B 起的出厂形态**）：worker 一个特权二进制都不 exec，每个文件步骤与槽位身份都以 `{sandbox_id, op}` 交给控制面，由控制面指令本节点的 agent 执行（`E2B_C3_AGENT_MAINT_URL`/`_MAINT_PORT`，见下）。`auto`：与 `agent` 等价（agent 是唯一剩下的特权形态）。**取值是闭列表**：`auto` / `agent`；`exec`（worker 自己 exec 镜像里的 file-capability 二进制）与 `socket`（C1 的每节点 root broker）**都已退役**（2026-09-30，N52；`socket` 更早随 C3 Task 7 的 DaemonSet 一起），现在被这个开关**具名拒绝**，不是静默回落。没有 agent 又不是 root 的 worker 保留进程内 E5.1 形态（无 per-sandbox host uid、无 route-B）并在启动时打一条 WARNING。运维含义：出厂形态是 `agent`；遗留的 `E2B_PRIV_HELPERS` 与 `E2B_PRIV_HELPER_SOCKET` 都是惰性残留。 |
| `E2B_PRIV_HELPER_SOCKET` | **已移除（C3 Task 7）** | C1 的 `socket` transport 连的那个 unix socket（`/run/e2b-broker/broker.sock`，hostPath `/run/e2b-broker`）。它随 `e2b-priv-broker` DaemonSet 一起退役：worker 与节点组件之间不再有这条通道，k8s 清单里也不再有这个 hostPath、这个 env 和 `wait-for-broker` 闸门。**留这一行只为让旧配置有个解释**：现在把 `E2B_PRIV_HELPER_TRANSPORT` 设成 `socket` 会在启动时被点名拒绝。节点上若还留着 `/run/e2b-broker/` 空目录，那是历史残留（hostPath 是 `DirectoryOrCreate`），可随手删。 |
| `E2B_C3_AGENT_URL` | 空（k8s 走 pod API；compose 默认 `http://c3-agent:49985`） | **C3 Task 3** 的 CP→agent 面 A 端点：`grant-slot`（写 `uid_map`）。k8s 不设（按 worker pod → `spec.nodeName` → 本节点 agent pod 的 label 查），compose 指向 agent 服务名，且该 URL 的**主机名就是 agent 自己的身份**（D12）。 |
| `E2B_C3_AGENT_MAINT_URL` / `_MAINT_PORT` | 空 / `49986` | **C3 Task 4 片 B（裁定 D22）** 的**面 B 端点**：`chown`/`rm`/`walk`。两个面必须是两个进程（面 A 要 uid 65534 才写得进 `uid_map`；面 B 要 uid 0 才能在 NFS 上 `chown`，且只有它挂了四个根），因此是两个监听——k8s 用同一个 pod IP 的第二个端口（`_MAINT_PORT`，面 B 绑 49986），compose 用第二个服务名（`_MAINT_URL` → `c3-agent-maint:49986`）。compose 未设该变量时**每个文件 op 具名 503**（不回落面 A：那会变成"每个 chown 都 EPERM"的假权限 bug）。 |
