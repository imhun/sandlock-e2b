# N27 平台状态另起 BASE（`E2B_STATE_BASE`）实施计划

> **执行状态（2026-09-27 更新）**：**已上线** —— 同挂载 + 树根下沉（`<export>/workspaces/<id>` + `<export>/state/`），一次性迁移 `done=12 unknown=0`、`same_inode=yes`，集群验收过（`docs/deploy-clusters.md` §11/§12）。
> **仍有效的决定**：state base 关键字 helper（未设 = 逐字节零变化）+ 一次性 `rename(2)` 迁移（不用拷 GiB 级 checkpoint 镜像）。**已作废的假设**：**独立挂载**那版（含 `move_entry` 的 EXDEV 兜底）——裁定不写。
> **残留（非本计划引入）**：无根 pure identity 档下 `<export>` 一层能列出 `state`/`_secrets` 的**名字**（内容仍 EACCES）——由 N16 合成根收敛，**默认值切不切留给用户**（`docs/deploy-clusters.md` §11.2）。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让"沙箱看不到平台状态目录"从**形态侥幸**变成**路径结构事实**：新增 `E2B_STATE_BASE`，把 `_runtime`（record / 命令日志 / checkpoint 镜像）、`.route-b`、`.uid_pool.lock`、`.uid_reservations` 搬到沙箱路径空间**永远不经过**的目录，并给出一份可回退的一次性迁移。

**Architecture:** 落点是 `gateway_common/paths.py` 的**四个**路径 helper（`sandbox_runtime_dir` / `sandbox_record_path` / `sandbox_command_log_path` / `sandbox_checkpoint_dir`）：每个加一个 `state_base` 关键字，缺省等于 workspace base（**未设环境变量时逐字节零行为变化**）。worker 与 CP 的 `Settings` 各加 `state_base`（读 `E2B_STATE_BASE`），所有调用点改成用 settings 的值，而不是从树路径反推 base。**推荐的落地形态是"同一个 NFS 挂载内、树根下沉一级"**：`<export>/workspaces/<id>` + `<export>/state/...`，于是搬迁是**同一挂载内的 rename**（元数据级、秒级、可回退），既不用把 GiB 级 checkpoint 镜像 copy+校验，也不存在 EXDEV；只有当运维要求 state 走独立 export/PV 时才需要 `move_entry` 的 EXDEV 兜底（那时 `adopt_legacy_records` 与 park 的两处 `os.replace` 会跨挂载）。

**Tech Stack:** Python（`envd_service` worker / `control_plane` CP，FastAPI + pytest）、C（`deploy/priv/priv_common.c` 的 file-capability broker `e2b-maint`）、k8s 清单（kustomize overlay + `deploy/k8s-k0s/apply.sh`）、阿里云 NAS 静态 PV（NFSv4.0）。

## 需人拍板 / 外部前提

1. **形态 A 还是 B**：推荐 **B（同挂载、树根下沉一级）**——迁移是 rename，秒级、可回退、不需要跨挂载 copy+校验；A（state 走独立 export/PV）必须在代码里保留 EXDEV 兜底，并且要把 GiB 级 checkpoint 镜像拷一遍、逐文件校验。
2. **窗口批准**：迁移期间 `e2b-worker` 缩到 0，**现有沙箱全部消失**（数据保留，N20 那类语义）。
3. **`.route-b` 是否绑定本期**：它有独立收益（文档里带 egress-proxy 凭据，pure 形态下沙箱 uid 就是它的属主、**能读**），但也可以顺势改成 worker pod 的本地 `emptyDir`——那是更彻底的一刀，需要单独一次改动。

5. **是否顺带把 `.uid_reservations` / `_snapshots` / `_secrets` 一起排期**（本期只前两项；`_secrets` 与 O3 一起做）。
